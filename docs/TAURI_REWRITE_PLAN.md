# Reader Tauri 2 重构与功能保真计划

状态：已批准方向，第一阶段进行中  
目标平台：Windows、macOS、Linux、Android、iOS  
技术方向：Vue 3 + TypeScript + Vite 前端，Tauri 2 宿主，Rust/官方插件提供系统能力

## 1. 为什么重构

当前 Windows 解压目录约 340.8 MB，安装包约 101.6 MB，而渲染层构建产物约
13.7 MB。主要体积来自 Electron 携带的 Chromium/Node 运行时。此次工作的目标不是
单纯压缩 Electron，也不是重写阅读器 UI，而是在保留现有阅读能力的前提下更换宿主：

- 桌面端不再捆绑完整 Chromium；
- 最大限度复用 Vue、TypeScript、PDF.js、epub.js 与 foliate-js 代码；
- 同一套业务模型可运行在桌面、Android 与 iOS；
- 文件、进度和标注数据不再依赖桌面绝对路径；
- 每个迁移阶段均可回到当前 Electron 版本验证行为。

## 2. 不可破坏的产品能力

以下能力是迁移门槛，不允许以“后续再补”为理由在替换 Electron 时丢失。

### 2.1 格式与阅读定位

| 格式 | 当前引擎 | 滚动模式 | 分页模式 | 恢复锚点 | 必须保留的行为 |
| --- | --- | --- | --- | --- | --- |
| TXT/Markdown | 自研分块读取 | 是 | 是 | 字节偏移 | 编码检测、前后分块、精确进度、目录解析 |
| EPUB | epub.js | 是 | 是 | EPUB CFI + 页首锚点 | 章节跳转、跨章翻页、目录、样式设置 |
| PDF | PDF.js | 是 | 是 | 页码 | 懒渲染、目标页跳转、目录 destination |
| MOBI/AZW3 | foliate-js | 是 | 是 | foliate location | 章节跳转、跨章翻页、目录、样式设置 |

共同验收要求：

1. 鼠标滚轮、按钮和目录跳转保持可用；移动端增加点击热区和横向滑动手势。
2. 滚动/分页切换后位置不能明显漂移。
3. 关闭书籍、退出应用、应用异常退出后都能恢复到最近一次有效位置。
4. 0%、章节边界、文件尾、空章节和超大文件不能产生死循环或空白页。
5. 进度显示必须单调、可解释，并与恢复锚点分开保存。

### 2.2 标记、批注与书签

当前数据语义必须原样保留：

- TXT 高亮/批注：文本、行内范围、字节偏移、类型、批注正文、时间；
- EPUB 高亮/批注：一个或多个 CFI、文本、类型、批注正文、章节信息、时间；
- MOBI/AZW3 高亮/批注：location/CFI 集合、文本、章节信息、时间；
- 书签：四种格式均支持，锚点分别为字节偏移、CFI、页码或 location；
- 高亮和书签列表支持排序、按章节分组、跳回原文、删除；
- 手工目录的新增、删除与章节删除行为必须保留。

验收要求：创建、重启恢复、跳转、编辑批注、删除五条链路均通过；同一段落附近的
TXT 书签去重规则保持一致；旧版数据迁移失败时保留原数据并给出可重试状态。

### 2.3 书架与设置

- 导入单本或多本书、封面提取/自定义封面；
- 分类、置顶、阅读进度、删除书籍与清理缓存；
- 每本书独立的字体、字号、行距、主题、背景和滚动/分页模式；
- 目录侧栏、工具栏、批注面板的开关与返回层级；
- Windows 现有书架、进度、书签、高亮、手工目录和设置可迁移。

## 3. 目标架构

```text
Vue UI / 阅读引擎
        |
应用服务（书架、阅读会话、标注、设置）
        |
ReaderHost + LibraryRepository + AnnotationRepository
        |
Tauri 2 commands / 官方插件
        |
Rust 共享逻辑 + Windows/macOS/Linux/Android/iOS 原生能力
```

### 3.1 平台边界

渲染层不得直接访问 `window.electron`、Tauri `invoke` 或移动端 URI。第一阶段先引入
`ReaderHost` 接口和 Electron 适配器；Tauri 适配器实现同一接口。业务代码只依赖接口。

宿主能力包括：

- 选择书籍/封面；
- 读取二进制、读取 TXT 分块、检测编码；
- 导入书籍到应用托管目录；
- 解析 TXT 目录；
- 保存、读取、迁移和删除阅读进度；
- 关闭文件句柄、清理书籍缓存。

### 3.2 书籍身份与文件模型

新版本不使用绝对路径作为书籍主键。Android 返回 content URI，iOS 可能返回 file URI，
并且授权与路径都可能变化。统一模型：

```ts
interface LibraryBook {
  id: string
  title: string
  format: 'txt' | 'epub' | 'pdf' | 'mobi'
  managedFileName: string
  sourceUri?: string
  fingerprint: string
  importedAt: number
}
```

导入后将书籍复制到应用沙箱，以 `bookId` 关联进度、设置、标注、书签和目录。文件指纹用于
重复导入检测，不用作可变的显示标题。桌面旧路径只保留为迁移来源。

### 3.3 持久化

目标存储为 SQLite（结构化业务数据）+ 应用数据目录（书籍、封面、缓存）。不继续增加新的
`localStorage` key。建议表：

- `books`、`categories`、`book_categories`；
- `reading_positions`、`book_settings`；
- `bookmarks`、`annotations`；
- `manual_toc_items`、`schema_migrations`。

所有迁移必须使用事务；先复制/转换并验证数量，再标记迁移成功，最后才允许清理旧数据。

## 6. 风险与应对

1. **系统 WebView 差异**：EPUB iframe、选区 Range、CSS 分页在 WebView2、Android
   WebView 和 WKWebView 上可能不同。阶段 B 必须先做真实样机，而不是只验证编译。
2. **移动文件 URI**：不得假设所有来源都是可长期读取的路径；默认复制进应用沙箱。
3. **大二进制跨桥传输**：EPUB/PDF/MOBI 一次传输可能造成内存峰值。样机记录峰值，必要时
   使用流式/分块 command 或 Tauri asset protocol。
4. **CFI/location 兼容**：更换 WebView 后必须用旧数据样本验证跳转，不允许静默重置进度。
5. **本地存储迁移**：WebView origin 变化可能导致旧 `localStorage` 不可见；迁移工具需在旧
   Electron 版本导出或由升级安装阶段读取原数据目录。
6. **iOS 构建条件**：iOS 构建、签名和真机测试必须在 macOS + Xcode 环境完成。

## 7. 当前开发决策

- 选择 Tauri 2，不采用 Flutter 全量重写，也不使用仍依赖 Electron 桌面的组合方案；
- 先建立平台接口，再添加 Tauri，避免一次性替换造成不可定位的回归；
- 先做 Windows TXT/EPUB 垂直样机，再迁移所有数据与格式；
- 新代码使用 `bookId`，旧 `filePath` 仅用于兼容阶段；
- 在功能对齐和迁移验证完成前保留 Electron 构建链。
